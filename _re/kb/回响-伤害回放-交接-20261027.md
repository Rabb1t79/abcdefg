## 3. ABI（Dump 逐字节，勿改）

`K2_ApplyGameplayEffectToTargetWithClass`，ParmsSize **0x78**：

| 偏移 | 字段 | 大小 |
| --- | --- | --- |
| 0x00 | `GameplayEffect`（TSubclassOf\<UGameplayEffect\>，**要 UClass**） | 8 |
| 0x08 | `TargetAbilityCmp`（UHTAbilitySystemComponent*） | 8 |
| 0x10 | `ModifyData`（FBufferData） | 0x58 |
| 0x68 | `BuffEventType`（EBuffEventType，u8） | 1 |
| 0x69 | `bUsePredictionKey`（bool） | 1 |
| 0x6C | `ReturnValue`（FActiveGameplayEffectHandle） | 8 |

`FBufferData`，大小 **0x58**：

| 偏移 | 字段 | 类型 |
| --- | --- | --- |
| 0x00 | `BuffName` | FName（8） |
| 0x08 | `DynamicGrantedTags` | FGameplayTagContainer（0x20） |
| 0x28 | `nLevel` | int32 |
| 0x2C | `fDuration` | float |
| 0x30 | `ModifyDuration` | float |
| 0x34 | `fPeriod` | float |
| 0x38 | `nStackCount` | int32 |
| 0x3C | `fStrengthMult` | float |
| 0x40 | `fStrengthAdd` | float |
| 0x44 | pad | 4 |
| 0x48 | `nStartTime` | int64 |
| 0x50 | **Dumper 未导出的 8 字节尾部**（不加会整体错位） | 8 |

`FActiveGameplayEffectHandle`（8 字节）：`int32 Handle`@0、`bool bPassedFiltersAndWasExecuted`@4。

`EBuffEventType`：0=UNKNOW、1=BEGIN、2=PERIODIC、3=ENTER_BATTLE、4=LEAVE_BATTLE、5=FLOATING、6=HITBACK、7=HITDOWN、8=HITOUT、9=BELINKED、10=ENTER_AIM …

`HTAbilityCharacter::OnDamaged`（ParmsSize **0x148**）：`DamageAmount`@0x00、`HitInfo`(FHitResult)@0x08、`DamageTags`@0x110、`DamageGameplayEffect`@0x130、`InstigatorCharacter`@0x138、`DamageCauser`@0x140。

`HTAttributeComponent` 的 HP 读取：**`asc + 0x1A38`**（float）。
注意：这是 **ASC** 的偏移，在角色 actor 上读会得到 0（今天踩过）。

## 4. 今天实测到的硬结论

| 结论 | 证据 |

## 7. 今天踩的坑（完整清单，按损失排序）

### 7.1 把游戏卡死两次（最贵）

**写法**：在 UI 按钮回调里做全表遍历——

```cpp
FindNameIdByPath("/Script/HTGame.HTAbilityCharacter");  // FName 全表，秒级
g_ue.FindClassById(id);                                 // GObjects，秒级
FindFuncByName(ch_cls, "OnDamaged");                    // 只查直接 Children
```

**现象**：点按钮后游戏无响应，只能强杀。
**正确做法**：用分帧扫描（`ProbeScanStep` / `Level->Actors`），或从已知对象直接取 UClass（`actor + 0x10`），再沿 `SuperStruct@0x40` 上溯。
**教训**：**只读 ≠ 便宜**。我当时以"只读不调用所以安全"为由跳过了分帧，这是判断错误。

### 7.2 三道插件加载门槛（每道都浪费了一轮）

| 报错 | 原因 | 解法 |
| --- | --- | --- |
| `unknown-capability capability=ue5-functions` | manifest 声明了这版 Core 不认识的能力 | 删掉该能力声明 |
| `code=static-crt`（`RtlPcToFileHeader` 导入） | 用了默认静态 CRT | 加 `/MD` |
| `code=missing-cxx-throw-bridge` | C++ 插件必须导出异常桥 | 编入 `sdk/cpp/plugin_cxx_throw_bridge.cpp` |

排查入口：`Anomaly\logs\anomaly-runtime.jsonl`，筛 `component=plugin-manager`。

### 7.3 `ufn=0`：`FindFuncByName` 只查直接 Children

蓝图类（`player_036_zankou_C`）上查不到 `OnDamaged`，它声明在祖先 `AHTAbilityCharacter` 上。
**解法**：沿 `UStruct::SuperStruct`（`+0x40`）上溯，最多 8 级。实测 `depth=3` 命中。

### 7.4 `od: call` 静默不执行

条件里写了 `g_pe_addr != 0`，而那个全局只有装了 PE 钩子才有值 → 整段被跳过，日志里连行都没有。
**解法**：用 `base + 0x3E41360`（`ApplyGEDirect` 里已在用的同一算式）直接取 ProcessEvent。
**教训**：探针的"没输出"要先怀疑条件不成立，不要先怀疑逻辑。

### 7.5 HP 读成 0：读错对象

`asc + 0x1A38` 是 **ASC** 的 HP 偏移；在角色 actor 上读得到 `0.0` 且 `SafeF32` 仍返回成功，**不会报错**，极易误判成"HP 为 0"。

### 7.6 `FBufferData` 比 Dumper 列出的字段多 8 字节

按字段算到 `nStartTime`(0x48) 结束只有 0x50，实际结构是 0x58 → `static_assert` 直接失败。
**解法**：补 `pad50[8]`，并把 `static_assert(sizeof(FBufData) == 0x58)` 留在代码里当护栏。

### 7.7 记录里的原生 RVA 不可用

`dump-5.6.1.md` 记的 `K2_ApplyGameplayEffectToTargetWithClass → 0x7778E50`，运行时按名解析到的却是完全不同的地址（另一个 build）。
**结论**：只能运行时按名字解析，**不要用文档里的 RVA 直接 call**。

### 7.8 新增插件目录必须重启游戏

宿主在启动时建立插件 catalog，运行中新增目录不会被发现（界面点启用必然失败）。
但**替换已有插件目录里的 `plugin.dll` 是热重载**，不用重启。

### 7.9 编码类误判（宿主侧，附带记一下）

- 用 `Encoding.ASCII` 去匹配 Core 里的中文字符串必定假阴性，**中文判据必须用 UTF-8**；
- `Start-Process` 在本机会因环境块里 `http_proxy`/`HTTP_PROXY` 大小写重复而抛异常，用 `&` 直接执行或先清空代理变量。
