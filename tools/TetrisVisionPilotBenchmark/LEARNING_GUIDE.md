# CPU / GPU 对照测试说明

## 比较原则

CPU 与 GPU 使用同一套棋盘规则、同一字典序评估目标、同一当前块 + 最多两个 NEXT 的前瞻序列。测试时应保持游戏窗口尺寸、帧率、棋盘状态和 NEXT 识别数量一致。先分别运行 CPU 与 GPU 多轮，记录：

- 搜索耗时：从收到棋盘/NEXT 输入后完成求解的计算时间。
- GPU 初始化耗时：首次创建设备/着色器/缓冲区的冷启动时间，单独显示。
- 输入链路耗时：从开始执行旋转/横移到发送硬降并完成落点复核。
- 端到端耗时：从本次求解开始到程序确认下一块出生。
- 多行消除结果：计划中的两行及以上清除次数、实际 SCORE 变化和游戏反馈。

CPU 统计的是实际遍历的合法搜索节点；GPU 统计的是扩展槽位数。两个后端的搜索计数口径不完全相同，不能仅凭节点计数认定谁做了更多相同工作。比较吞吐时以多次稳态搜索耗时、完整端到端时间和实际清行表现为准。

## 一秒双行目标

求解器先比较可放置方块数，再优先当前这一步立即消除两行及以上，然后才比较前瞻内累计的多行消除事件。这是规划偏好，不是对每个随机棋盘都能形成双行清除的保证。日志中会记录计划消除数与实际执行耗时。需要区分纯搜索时间是否低于 1 秒、输入和游戏响应是否让完整动作链低于 1 秒，以及当前棋盘/可见 NEXT 是否真的存在双行清除路线。

## 透明方块与记忆

每次确认 NEXT 方块出生后，程序将上一块的预测锁定棋盘提交为当前记忆，再用当前可见固定格校验。每次落块都有独立实例 ID 和形状令牌（`S`、`T1–T4`、`L1–L4`、`<L1–<L4`、`Z1–Z4`、`<Z1–<Z4`、`I1–I4`）。旋转相位按顺时针方向从 1 开始编号。程序从每次 NEXT 出生时初始化相位，并在旋转动作经视觉复核后更新 0–3 相位，因此即使 `I`、`Z`、`<Z` 的 180° 后占格轮廓重复，也能保留输入过程中经过的第 3、4 相位；求解器仍只用实际不同的轮廓做碰撞计算。首次启动时若当前方块已经离开出生区，单凭截图无法判断对称方块此前是否旋转过 180°，首块只能以当前可见轮廓作为相位起点。档案逐次保存 10×20 棋盘快照和 200 格的归属 ID。消行时棋盘和归属表一起压缩，所以残留碎片仍可追溯到原方块实例。程序重新启动时会询问恢复上次档案还是开启新会话；选择恢复后，若当前画面出现档案中不存在的格子，会停止而不猜测。CSV 每行还记录来源/结果棋盘哈希、落点、消行数、分数快照、计算/输入/端到端时间和 CPU/GPU 后端代码。

这套记忆不是对任意截图的“透视恢复”。如果首次启用新版本时隐藏格已经存在、此前从未被识别或记忆，程序没有数据来源去推断它们。此时只能从可识别局面开始；后续已经写入事件档案的格子可以在透明后继续保留，并能跨程序重启恢复。

## 按键时延

方向键是一格一发的独立短点按，不使用按住方向键进行跨格移动。程序使用高分辨率计时器与 QPC 忙等来缩短 key-down 脉冲，默认 1 ms；但 Windows 的输入注入、游戏帧循环和设备刷新不会因此变成零延迟。必须以日志中的输入与端到端实测为准。
